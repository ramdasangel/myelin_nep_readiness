# Regeneration: c5_student_dashboard.html

**Stage:** C5 — Student Online Assessment Dashboard
**Output:** `output/c5_student_dashboard.html`
**Generator:** Inline Python script (see Step 3 below)

## Overview

Self-contained HTML dashboard showing detailed student-level results from the NEP Sharable Exam (MathAngle Adaptive Assessment). Covers 6 teachers across 4 schools, with per-student scores, exit levels, Bloom's cognitive analysis, and topic/competency mastery breakdowns.

## Data Sources (Prod MongoDB Collections)

| Collection | Purpose | Key Fields |
|------------|---------|------------|
| `UserTemp` | Teacher profiles | `firstName`, `lastName`, `RoleName`, `selectedBranchId` |
| `SchoolBranches` | School/branch names | `BranchName`, `School.SchoolName` |
| `SharableDiagnosticUserTempMapping` | Teacher → exam link | `userTempId` (ObjectId), `diagnosticExamId`, `maxShareExamCount`, `CurrentRegistrationCount`, `referalCode`, `isActive` |

| `nepStudentExamEnrollment` | Student → exam enrolment | `diagnosticExamId` (ObjectId), `userTempStudentId`, `referralCodeUsed` |
| `OnlineAssesmentStudentResult` | Raw student responses | `OnlineAssesmentID` (ObjectId), `StudentID`, `TotalObtainedMarks`, `SubmitFlag`, `AssesmentResult[]` |

| `Students` | Student profiles | `StudentFirstName`, `StudentLastName`, `Class` |

## Step-by-Step Regeneration

### Step 1: Upload extraction script to prod

The extraction script queries all 10 collections listed above and produces a single JSON file with the complete data structure.

```bash
scp -i ~/.ssh/$SSH_KEY \
  scripts/extract_nep_sharable.js \
  $PROD_USER@$PROD_HOST:~/myelin_stat_ro/
```

### Step 2: Run extraction on prod

```bash
ssh -i ~/.ssh/$SSH_KEY $PROD_USER@$PROD_HOST \
  'mongosh --port 27017 -u $MONGO_USER -p "$MONGO_PASS" \
   --authenticationDatabase pdea_pilot pdea_pilot --quiet \
   ~/myelin_stat_ro/extract_nep_sharable.js \
   > ~/myelin_stat_ro/nep_sharable_output.json 2>&1'
```

### Step 3: Transfer JSON to local

```bash
scp -i ~/.ssh/$SSH_KEY \
  $PROD_USER@$PROD_HOST:~/myelin_stat_ro/nep_sharable_output.json \
  output/nep_sharable_exam_data.json
```

### Step 4: Generate the HTML dashboard

The dashboard is generated by a Python script that reads the JSON data and produces a self-contained HTML file with all data embedded inline.

```bash
python3 scripts/gen_c5_student_dashboard.py
```

This reads `output/nep_sharable_exam_data.json` and writes `output/c5_student_dashboard.html`.

> **Note:** If the generator script does not exist, the dashboard was originally created inline. The embedded JSON data sits inside a `const DATA = [...]` block in the HTML `<script>` section. To manually update:
> 1. Open `output/nep_sharable_exam_data.json`
> 2. Restructure per the compact format (teacher/student/scores/cognitive/topics)
> 3. Replace the `const DATA = [...]` array in the HTML

### Step 5: Clean up prod temp files

```bash
ssh -i ~/.ssh/$SSH_KEY $PROD_USER@$PROD_HOST \
  'rm -f ~/myelin_stat_ro/extract_nep_sharable.js ~/myelin_stat_ro/nep_sharable_output.json'
```

## Extraction Script Details (`scripts/extract_nep_sharable.js`)

The script iterates over the 6 teacher userIds and for each:

1. Looks up `UserTemp` for teacher profile
2. Finds active `SharableDiagnosticUserTempMapping` record → gets `diagnosticExamId`
3. Looks up `Diagnostic` → gets `onlineAssesmentID`, subject, standard, branchCode
4. Looks up `SchoolBranches` → gets school/branch names
5. Queries `OnlineAssesmentQuestions` → gets question bank metadata (level, cognitive, topic distribution)
6. Queries `nepStudentExamEnrollment` → gets enrolled student count
7. Queries `OnlineAssesmentStudentResult` → gets per-student raw scores (obtained/total, submitFlag)
8. Queries `OnlineAssesmentAnalysisStudentLevel` → gets detailed breakdowns:
   - `Question_Level_wise_count[]` — Level 1/2/3 right/wrong/total (exit level = highest attempted)
   - `CognitiveLevel_wise_count[]` — Bloom's taxonomy scores (Remembering → Creating)
   - `Topic_wise_count[]` — Chapter → topic right/wrong with prerequisite skills
   - `Predecessor_wise_count[]` — Per-competency mastery percentages
9. Joins `Students` collection for student names

## Dashboard Structure

The HTML dashboard contains 5 views per teacher:

| Tab | Content |
|-----|---------|
| **Student Scores** | Ranked table: name, marks (obtained/total), score bar, time taken, exit level badge |
| **Exit Levels** | Per-student Level 1/2/3 question breakdown (right/total at each adaptive level) |
| **Cognitive Analysis** | Bloom's taxonomy aggregate bars + per-student detail (Remembering, Understanding, Applying, Analyzing, Evaluating, Creating) |
| **Topic/Competency** | All topics sorted by mastery %, with chapter, prerequisite skill, right/total counts |
| **Overview Charts** | Exit level distribution + score band distribution (90-100%, 70-89%, 50-69%, 30-49%, 0-29%) |

## Key Concepts

### Adaptive Testing & Exit Levels
Each exam has 60 questions (20 per level). The adaptive engine moves students from Level 1 → 2 → 3 based on performance. The **exit level** is the highest level where the student attempted questions:
- **Level 1** (Basic) — foundational skills
- **Level 2** (Intermediate) — application and reasoning
- **Level 3** (Advanced) — higher-order thinking

### Cognitive Levels (Bloom's Taxonomy)
Each question is tagged with a Bloom's level via `CognitiveLevels` field:
- Remembering → Understanding → Applying → Analyzing → Evaluating → Creating

### Competency / Prerequisite Skills
Each topic has a `Predecessor` field identifying the prerequisite skill needed. The `Predecessor_wise_count` in the analysis collection provides per-skill mastery percentages.
